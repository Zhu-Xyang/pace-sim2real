# 延时设计说明

本文说明 PACE 里「延时 $T_d$」这一项的原理、论文的原始定义、仓库实现与论文的差异，
以及我们在 S800 / G1 上踩过的坑与现行取值。相关文档：
[`phase_margin_analysis.md`](phase_margin_analysis.md)（S800 的相位裕度实例）、
[`damping_ratio_analysis.md`](damping_ratio_analysis.md)（增益设计配方）、
`docs/g1_sim2sim_guide.html`（G1 参考运行，用指令延时执行器）。

---

## 一、这一项在辨识什么

延时的物理来源有几处，论文把它们**合并成一个全局集总延时** $T_d$（lumped delay）：

- 上位机 → 电机控制器的指令链路（总线周期、固件缓冲）
- 控制周期离散化本身
- 滤波器、固件补偿、未建模电子学

论文原文（§2.2）：

> Residual effects from firmware compensations, filtering, and unmodeled electronics are not
> parameterized individually but are instead captured implicitly through the effective inertia
> $I_a$, damping $d$, and lumped delay $T_d$. This abstraction avoids introducing weakly
> identifiable parameters while preserving the dominant joint-space dynamics.

所以参数向量是

$$p = [I_a,\ d,\ \tau_f,\ \tilde q_b,\ T_d]^\top \in \mathbb{R}^{4n+1}$$

$T_d$ 是**全局标量**（所有关节共用一个），与逐关节的 $I_a/d/\tau_f/\tilde q_b$ 一起辨识。

---

## 二、论文把延时放在哪一环（关键）

论文用 Eq. (1) 描述关节的闭环跟踪动力学：

$$H_q(s) = e^{-sT_d}\cdot\frac{P_\tau}{I_a s^2 + (d + D_\tau)s + P_\tau}$$

$P_\tau, D_\tau$ 是 PD 增益，$I_a$ 是等效电枢惯量，$d$ 是粘性阻尼。

**注意延时的位置**：$e^{-sT_d}$ 乘在**输入（参考）通道**上，分母——也就是特征方程
$I_a s^2 + (d+D_\tau)s + P_\tau = 0$——**里面没有延时**。这意味着论文模型里：

- 闭环极点与 $T_d$ **无关**；
- $T_d$ 只改变跟踪相位，不参与稳定性。

也就是说，**论文的模型就是「指令延时」**：控制器用当前的状态反馈、滞后的参考指令。

⚠️ 而仓库里从 ANYmal 继承下来的 `PaceDCMotor`（`utils/pace_actuator.py`）是把延时加在
**输出力矩**上的（`torques_delay_buffer.compute(control_action_sim.joint_efforts)`）。那对应的
特征方程是 $I s^2 + d\,s + (P_\tau + D_\tau s)e^{-sT} = 0$，**与 Eq. (1) 不符**。

> **结论：把延时从力矩挪到指令，不是偏离论文，而是回到论文。**
> 现有实现才是那个偏离项（它是 ANYmal 时代沿用 `DelayedPDActuator` 的历史包袱）。

⚠️ 精确地说，有两点要交代清楚，否则容易把结论说过头：

1. 论文自己注明了 Eq. (1) 是**理想化线性模型、"仅用于频域分析"**（假设内环力矩跟踪带宽足够高、
   忽略饱和等非线性），它并不是仿真器里的实现说明。但 §2.2 把辨识参数直接命名为
   **"a global command delay $T_d$"**，且 Eq. (1) 里延时不进特征方程 —— 命名和频域模型
   都指向**指令链路**，这是论文给出的口径。
2. 两种结构**当延时相对环路相位裕度很小时结果接近**（力矩延时只是多贡献一份回路内相位滞后
   $\omega_c T$）。ANYmal 的 7.5 ms 配它的低增益时这点差别可以忽略，所以那边两种写法都"能用"；
   但**G1 的高增益 + 12.5 ms 让这点差别变成了"稳 / 不稳"**（见第五节）。
   这不是"两种写法等价"的问题，而是"在什么增益下才等价"的问题。

### 上游实现与 Eq. (1) 的不一致（不是本项目引入的）

`utils/pace_actuator.py` 是 PACE 作者本人的实现，它的 docstring 写得很明确：

> The torque command computed by the PD controller is applied after a configurable delay
> (in simulation steps) to represent latency between command calculation and actuation.
> **The software implementation is inspired by `DelayedPDActuator`.**

即：**延时加在力矩上，且是照搬 Isaac Lab 现成的 `DelayedPDActuator` 的做法**。所以论文
Eq. (1)（延时在输入通道）与作者自己的参考实现在"延时放在哪一环"上**是不一致的**，
这一致性问题在**上游代码里**，不是我们改出来的。

那到底哪个才是仿真里真正起作用的？**实现说了算**，有两条实测证据：

- S800 用**力矩延时**的 PM 公式预测出 ELBOW_YAW 的 PM = $-12^\circ$、$\omega_c$ = 12.3 Hz，
  实测自激振荡频率 **12.5 Hz** —— 吻合（`phase_margin_analysis.md`）。
  如果延时真在输入通道、不进回路，这个关节根本不会振。
- 把 `delay_gt` 从 5 改成 0 重采，G1 全部关节 >10 Hz 能量从 27% 掉到 ≤0.2% ——
  只有回路内的延时才会这样改变稳定性。

所以对**仿真**而言，必须按「力矩延时」来分析（$\omega_c T \lesssim 0.613$ rad 那条约束成立）；
论文 Eq. (1) 应理解为面向频域分析、把集总延时简化到输入端的近似模型 —— 这个简化在
ANYmal 的低增益/小延时下无害（$\omega_c T\approx 0.24$ rad ≈ 13°），在高增益下则会给出
**偏乐观**的结论。

论文实测的 $T_d$：**ANYMAL 与 TYTAN 都辨识出 7.5 ms**（§4）。论文同时给出频率响应验证：
辨识出的模型到 25 Hz 相位滞后 ≤ 5°、幅值接近 0 dB，从相位斜率反推的死区时间 ≈ 400 µs
（那是电机的电流环内环，与 $T_d$ 不是一回事）。

## 三、两种结构：时域方程先行

频域（传递函数）只能回答"**会不会**振"，时域（微分方程）才能回答"**为什么参数差 $10^{-6}$
轨迹就完全不同**" —— 而后者才是拟合失败的根因。所以先写时域。

### 3.1 论文（Eq. 1）的时域形式

把 $H_q(s) = e^{-sT_d}P_\tau/(I_a s^2 + (d+D_\tau)s + P_\tau)$ 反变换回时域：

$$I_a\,\ddot q(t) \;+\; (d + D_\tau)\,\dot q(t) \;+\; P_\tau\,q(t) \;=\; P_\tau\,q_{des}(t - T_d) \;+\; P_\tau \tilde q_b
\tag{T1}$$

**延时只出现在等号右边**：反馈项 $q(t)$、$\dot q(t)$ 用的都是**当前**状态，只有参考指令滞后。
（注意 $D_\tau$ 只出现在左边当作附加阻尼、不出现在右边 —— 这正是"$D$ 项作用在测量的速度上"的写法，
与 Eq. (1) 分子只有 $P_\tau$ 一致。）

### 3.2 代码实现（`PaceDCMotor`）的时域形式

代码把**算好的力矩**存进延时缓冲再取出来施加，即 $\tau_{applied}(t) = \tau_{PD}(t-T)$。
而 $\tau_{PD}$ 是用**当时**的状态算出来的，所以延迟的力矩里**带着延迟的状态**：

$$I\,\ddot q(t) + d\,\dot q(t) + \tau_f\operatorname{sgn}\!\big(\dot q(t)\big)
\;=\; P_\tau\big[q_{des}(t-T) - q(t-T)\big] \;-\; D_\tau\,\dot q(t-T) \;+\; P_\tau\tilde q_b
\;-\;\underbrace{\Delta_{sat}(\cdot)}_{\text{力矩-转速曲线/限幅}}
\tag{T2}$$

**延时出现在等号右边的反馈项里**：反馈用的是 $q(t-T)$、$\dot q(t-T)$，不是当前状态。
（$\tilde q_b$ 是常数，延不延时无差别；$\tau_f$ 与饱和是**当前**的非线性项。）

### 3.3 一字之差，数学性质完全不同

| | 论文 (T1) | 代码 (T2) |
|---|---|---|
| 反馈用哪个状态 | 当前 $q(t)$ | **$T$ 之前的** $q(t-T)$ |
| 方程类型 | 常系数 **ODE** | **延时微分方程（DDE）** |
| 特征方程 | $Is^2+(d+D)s+P=0$，**代数方程、有限个根** | $Is^2+ds+(P+Ds)e^{-sT}=0$，**超越方程、无穷多个根** |
| 延时是否在回路内 | 否（只在激励项） | **是** |
| 会不会自激 | **不会**（正增益下极点恒在左半平面） | **会**（Hopf 分岔：$T$ 增大到某一值后有一对根越过虚轴） |
| $T$ 的作用 | 只让关节"跟得晚一点" | 直接决定稳定与否 |

一句话：**论文里延时是"参考走慢了"，代码里延时是"反馈瞎了 $T$ 那么久"**。
后者能自激、前者不能 —— 这就是为什么同一个 $T_d$ 数值，在两种写法下含义完全不同。

### 3.4 频域：相位裕度与硬带宽上限

设 $C(s) = kp + kd\cdot s$，被控对象 $G(s) = 1/(I s^2 + B s)$。力矩延时的回路由 (T2) 线性化得到，
在增益穿越频率 $\omega_c$ 处的相位裕度是

$$PM \;=\; \underbrace{\arctan\frac{kd\,\omega_c}{kp}}_{\text{D 项超前，}\le 90^\circ}
\;+\; \underbrace{\arctan\frac{B}{I\omega_c}}_{\text{粘性阻尼，}\le 90^\circ}
\;-\; \underbrace{\omega_c T}_{\text{延时，无上限}}$$

前两项有上限、第三项随频率**线性增长**（纯延时 $e^{-sT}$ 的相位 $=-\omega T$ 无上限，D 项最多
补 $+90^\circ$，补不回来），所以存在一条**工程用硬带宽上限**：

$$\boxed{\;\omega_c T \lesssim 0.613\ \text{rad}\;}\quad(\text{即 } PM\gtrsim 35^\circ)$$

这个常数由 S800 文档的实例反推：$T=12.5\,\text{ms}$ 时 $\omega_c\lesssim 7.8\,\text{Hz}$
⇒ $\omega_c T = 2\pi\cdot 7.8\cdot 0.0125 = 0.613$。**它只对力矩延时成立**——
指令延时结构下这条约束根本不存在。

### 3.5 临界延时：可以精确算，而且已被实测验证

工程上限（3.4）是近似；**精确的线性稳定边界**要把 (T2) 的特征方程
$Is^2 + ds + (P+Ds)e^{-sT}=0$ 令 $s=j\omega$ 解出来，得到一对 $(\omega_{crit}, T_{crit})$：
$T_{crit}$ 就是**临界延时**（超过它该关节必自激），$\omega_{crit}$ 是起振频率。

验算：用 `phase_margin_analysis.md` 里那个 S800 实例（$I{=}0.0103, d{=}0.1, kp{=}50, kd{=}0.474$），
本方法给出 $T_{crit} = 9.80$ ms、$f_{crit} = 12.3$ Hz；而该文档记录**实测自激 12.5 Hz**，
且当时用的正是 12.5 ms $> 9.80$ ms。**频率误差 1.6%，方向一致** —— 时域模型成立。

G1 腿部（注入真值 $I_a{=}0.01$、$d{=}0.05$，kp/kd 取当前 cfg，$\text{dt}=2.5$ ms）：

| 关节类型 | 临界延时 $T_{crit}$ | 起振频率 $f_{crit}$ | 用 12.5 ms 时 | 用 5 ms 时 |
|---|---|---|---|---|
| HIP_PITCH | 61.1 ms | 1.1 Hz | ✓ 稳 | ✓ 稳 |
| HIP_ROLL | 53.9 ms | 2.0 Hz | ✓ 稳 | ✓ 稳 |
| HIP_YAW | 23.8 ms | 8.8 Hz | ✓ 稳（余量 11 ms） | ✓ 稳 |
| KNEE | 24.6 ms | 8.3 Hz | ✓ 稳（余量 12 ms） | ✓ 稳 |
| **ANKLE_PITCH** | **10.4 ms** | 22.7 Hz | **✗ 越过 2.1 ms** | ✓ 稳（余量 5.4 ms） |
| **ANKLE_ROLL** | **8.6 ms** | 27.9 Hz | **✗ 越过 3.9 ms** | ✓ 稳（余量 3.6 ms） |

这与实测完全对上：**出带能量最严重的正是踝**（腿部数据 hip_yaw 54.6% / ankle_pitch 49.4%，
全身数据 ankle_roll 15.2%）；而"为什么全腿都看到**同一个** 18.9 Hz"也能解释 ——
踝起振后通过**腿内的运动学耦合**传到整条腿链（支链之间才解耦，支链内部不解耦）。
改到 5 ms 后踝的余量回到 3.6 ms，实测出带能量 27% → 0.05%。

> 工程建议：按 3.5 算出每个关节的 $T_{crit}$，**取用的 $T$ 不要超过最小 $T_{crit}$ 的 ~60%**。
> 3.4 的 $\omega_c T\lesssim0.613$ 可作快速估算，但边界附近应以 $T_{crit}$ 为准。

自己算（把 $I, d, kp, kd$ 换成目标关节的值即可，不依赖 Isaac Sim）：

```python
import numpy as np, math
def hopf(I, d, P, D):
    """力矩延时环路的临界延时 T_crit [s] 与起振频率 f_crit [Hz]。
    特征方程 I s² + d s + (P + D s)e^{-sT} = 0，令 s = jω 求解。"""
    def cs(w):                                  # [P, Dw; Dw, -P][c,s] = [Iω², -dω]
        return np.linalg.solve(np.array([[P, D*w], [D*w, -P]]), np.array([I*w*w, -d*w]))
    ws = np.linspace(1e-3, 4000, 400000)
    r = np.array([np.sum(cs(w)**2) - 1.0 for w in ws])
    for i in range(len(ws) - 1):
        if r[i] * r[i+1] < 0:
            w = ws[i]; c, s = cs(w); T = math.atan2(s, c) / w
            while T <= 0: T += 2*math.pi / w
            return T, w / 2 / math.pi
T_crit, f_crit = hopf(I=0.0104, d=0.05, P=28.50, D=1.814)   # G1 ANKLE_ROLL
print(f"T_crit = {T_crit*1000:.2f} ms, f_crit = {f_crit:.1f} Hz")
```

（$I$ 取 $I_{link}+I_a$：$I_{link}$ 见 `g1_pace_env_cfg.py` 的极点表，$I_a$ 是注入的 armature 真值；
kp/kd 取 cfg 里该关节的实际增益。）

### 3.6 离散时间：为什么延时是整数、为什么取整必须 round

仿真里的延时是**整数步**，所以 (T2) 实际是离散形式

$$\tau[k] \;=\; P_\tau\big[q_{des}[k-N] - q[k-N]\big] \;-\; D_\tau\,\dot q[k-N],
\qquad N \in \{0,1,\dots,\text{max\_delay}+1\}$$

后果有两个：

- 目标函数对连续参数 $\theta$ 是**阶梯状**的（$\theta$ 每跨过一个整数，行为突变一次）。
  这使得"钉死延时逐个扫描"（`--fix_delay`）比让优化器自己找更可靠。
- 取整方式决定真值落在格子**边界**还是**中心**：`to(torch.int)` 是截断（$\theta\in[5,6)$ 才是 5），
  真值 5.0 恰在边界上 —— floor test 把框收缩到 $\pm10^{-6}$ 时会劈成两半
  （实测一半样本延时 4，损失差 **9 个数量级**）。必须用 `torch.round`，让真值落在 $[4.5,5.5)$ 的中心。

## 四、为什么"位置"比"数值"更要紧

超限之后不是"拟合变差一点"，而是系统的**性质**变了。用 3.2 的时域方程可以精确说清链条：

1. **闭环越过 Hopf 边界 → 极限环。** 线性理论预测"会不会振 + 振在什么频率"
   （3.5 已验证频率误差 1.6%）；**幅度**由非线性（力矩-转速曲线、effort limit、库仑摩擦）决定，
   线性理论管不到。
2. **临界点附近系统是"病态敏感"的。** 极限环幅度 $A \propto \sqrt{\mu}$，其中 $\mu$ 是越过边界的
   距离（Hopf 分岔的标准结果）。于是
   $$\frac{\partial A}{\partial \theta} \;\propto\; \frac{1}{2\sqrt{\mu}} \;\xrightarrow[\mu\to 0]{}\; \infty$$
   **参数只差 $10^{-6}$，幅度就能差出量级** —— 损失地形在真值附近不是斜坡而是**悬崖**。
3. **振荡的相位是一个中性方向。** 极限环沿相位方向的 Floquet 乘子恒为 1：任何扰动都会把振荡相位
   平移一点，而 20 s 的轨迹足够让这点相位差与数据完全去相关。于是"稍微错"的仿真与数据
   在振荡上**对不上拍**（损失巨大），而"把振荡压掉"的仿真损失反而更低。
4. 于是优化器最理性的选择是**离开正确解**。实测观察到的补偿方向完全吻合：
   `delay↓`（远离 Hopf 边界）+ `friction↑`（描述函数意义上加阻尼）+ `viscosity` 反向对冲
   + `bias` 撞墙吸收残余。

**这个"离开"是两段式的，值得单独说清楚**（G1 那轮实测）：

1. **先翻越 Hopf 悬崖。** 只要搜索框里装着越界样本，它们的分数就被极限环主导 ——
   在种群里的相对优劣基本是**噪声**（谁的振荡相位碰巧对上数据），CMA-ES 拿到的是垃圾排序。
   于是它朝"分数确定更低"的方向走，而那个方向就是**往稳定区跑**：G1 失败那轮 delay 均值
   一路下滑 5.04 → 3.03 → 1.79 → 1.51 → 0.36，不是"用短延时补相位"，是**在翻越悬崖**。
2. **再被补偿谷拉走。** 到了稳定侧，损失重新变成参数的正常函数，但一个错的延时可以部分被
   friction/armature 抵消 —— 于是停在错解上（armature 贴下界、friction 贴上界、bias 撞墙）。

**量级参照**（G1 腿部，$\text{dt}=2.5$ ms）：踝的 $T_{crit} = 8.62$ ms = **3.45 步**。
旧搜索框 $[0,10]$ 步里只有最下面 1/3 稳定，而初值（框的中点）恰好是 5 步
⇒ **初始种群几乎全部越界**，拟合从第 0 代起就在抽签。
新框 $[0,4]$ 步、初值 2 步、$\sigma\approx\pm1$ 步 ⇒ 初始种群落在 $[1,3]$ 步，**全部在稳定侧**。

> 所以"把延时降到稳定区"带来的不是"精度好一点"，而是**系统性质**的改变
> （混沌排序 → 正常排序）。G1 从失败到 75 代收敛（12 关节 ±0.9%）的差别，
> 经逐项比对确认**只来自延时相关的三处改动**（`delay_gt` 5→2、搜索上界 10→4、
> 取整截断→round）—— 其余设置（对数 armature、损失掩码、腿部单激励、3 Hz 带、
> 减半幅度）在失败那轮里就已经存在。

判据与症状（我们实测）：

| 指标 | 健康 | 病态 |
|---|---|---|
| 出带（>扫频上限）能量占比 | ≲ 1% | 27%~55% |
| 主频 | ≈ 扫频上限 | 远高于上限的固定频率（如 18.9 Hz） |
| floor test 在 ±1e-6 框内的样本散布 | ≈ 1 个数量级 | 4.5 个数量级 |
| 越过 $T_{crit}$ 的关节数 | 0 | 踝（2/6 类） |

## 五、两次实际踩坑

### S800

- **$T_d = 5$ 步 @400 Hz = 12.5 ms 是继承来的，不是测出来也不是设计出来的。**
  上游 `data_collection.py`（原本是给 ANYmal 用的，默认 task 就是 `Isaac-Pace-Anymal-D-v0`）
  里写死 `time_lag = torch.tensor([[5]])`；ANYmal 的 env cfg 与 S800 的 `max_delay`（10）、
  `sim.dt`（0.0025）**逐字相同**，是整份继承的关系。
  而论文在**真机 ANYmal 上辨识出的延时是 7.5 ms**（§4），并不是 12.5 ms。
- ⚠️ **因果要摆正**：不是"延时按增益设计"，而是**增益去迁就这个继承来的延时** ——
  那 5 个轻惯量关节的 kp 之所以下调到 PM=30°，正是因为 12.5 ms 太长。所以
  "增益现在稳定了"**不能反过来证明 12.5 ms 是对的**（循环论证）。
- 当时的实测：照搬**真机部署增益**时，5 个轻惯量关节 PM 掉到 $-12^\circ$（ELBOW_YAW）、
  9.2°（SHOULDER_YAW）、8.3°（ANKLE_ROLL），无预警自激，振荡频率 12.5 Hz ≈ 预测
  $\omega_c$ 12.3 Hz。修法是这 5 个的 kp 下调到 PM=30°（详见 `phase_margin_analysis.md`）。
- ⚠️ **而且那次修复（commit `2124cf0`，9/29 14:51）比数据采集（9/29 12:41）晚了 2 h 10 min**，
  改动涉及 14 类关节里的 12 类 kp（HIP_ROLL 742→200、HIP_PITCH 633→240 …）。
  后果：`26_09_29` 那批数据是用**旧增益**采的，却用**新增益**去拟合 →
  模型复现不出自己的数据（floor test 1.26e-3，而拟合自己到 1.77e-4）→
  拟合靠 friction 补偿 → 那几个关节出现 ±30~100% 的摩擦误差。
  把 cfg 增益回退到 9/28 版重跑同一 floor test：**1.26e-3 → 1.75e-6（好 720 倍）**，坐实。
- 真延时未知 ⇒ 若要更站得住脚，三选一：① 真机上用阶跃响应测；② 改用论文实测的
  ANYmal 量级 3 步（7.5 ms，$\omega_c$ 上限随之放宽到 ~13 Hz，那 5 个关节还能拿回一些 kp）；
  ③ 明确声明 12.5 ms 只是 round-trip 的一个人为选择。**任一都会要求重采数据。**

### G1

- **照抄了 S800 的 12.5 ms，却配了 BeyondMimic 的官方增益**（$kp = I_a\omega^2$，
  $\omega = 2\pi\cdot10$ Hz）→ 踝的 $\omega_{cl}=9.74$ Hz，相位滞后
  $2\pi\cdot9.74\cdot0.0125 = 43.8^\circ > 35.1^\circ$ 上限 ✗。
- 实测：腿部数据里 **hip_yaw 54.6%、ankle_pitch 49.4%** 的跟踪误差能量来自 18.9 Hz 极限环；
  拟合从第 0 代起 delay 均值 5.04 → 3.03 → 1.79 → 1.51 一路塌，armature 全贴下界、
  friction 全贴上界。
- **修法：$T_d$ 5 → 2 步（5 ms，滞后 17.5°）**，同时 `max_delay` 10 → 4、
  delay bounds 上界 10 → 4（真值落 50%，上限 4 步正好是踝的稳定边界）。

  跟踪误差 RMS 0.174 → 0.116 rad，floor test **1/32 → 32/32 到地板**

## 七、延时该放在哪一环：准则与真机测量

### 7.1 三种位置，只有两种在回路内

| 延时放在哪 | 时域方程 | 在回路内？ | 影响稳定性？ | 典型来源 |
|---|---|---|---|---|
| **传感器/测量** | $\tau = kp\big(q_d(t)-q(t{-}T)\big) - kd\,\dot q(t{-}T)$ | **是** | **是** | 编码器采样、状态估计、用回读的 $q$ 算 PD |
| **执行器/力矩**（现有代码） | $\tau = PD(t-T)$（整条 PD 律滞后） | **是** | **是** | 上位机算 PD + 总线往返 |
| **指令/参考**（论文 Eq.1） | $\tau = kp\,q_d(t{-}T) - kp\,q(t) - kd\,\dot q(t)$ | 否 | **否** | 电机端算 PD，只有下行指令有延时 |

两条关系要先记牢：

- **力矩延时 ≡ 传感器延时 + 指令延时**（前者把 $q_d$ 也一起滞后了）；
- **传感器延时与力矩延时的回路传递函数完全相同**（$L = C(s)P(s)e^{-sT}$），
  所以对稳定性而言两者等价 —— 只有"指令延时"是那个**不进回路**的特例。

所以"延时到底放 sensor 还是放论文那种"这个问题，本质上是问：
**$T$ 在回路内，还是在回路外。**

### 7.2 判断准则：看 PD 在哪算、数据从哪读

| 架构 | 回路内有延时吗 | 该用哪种模型 |
|---|---|---|
| 上位机算 PD（用总线读回的 $q$），力矩再经总线下发 | **有**（测量回传 + 指令下行） | **力矩/传感器延时**（现有 `PaceDCMotor`）。ANYmal 疑似这种 |
| 电机端算 PD（下发目标+增益，电机用自身编码器算） | 回路内几乎无延时；但**记录的数据**仍带总线回读延时 | **指令延时**（论文 Eq.1 / `PaceDCMotorCmdDelay`）|

对 G1：Unitree 的电机 SDK 消息里带 `q / dq / tau / kp / kd`，**PD 大概率在电机端用自身编码器算**，
上位机只下发目标与增益 ⇒ 接近"回路外"。但要把两段分开看，量级差一个数量级：

| 段 | 量级 | 是否在回路内 |
|---|---|---|
| 电机内部：编码器采样 + 电流环 | ~0.2–0.5 ms | **是**（论文在他们驱动器上由相位斜率实测死区时间 ≈ 400 µs） |
| 上位机 ↔ 电机总线：指令下行 + 数据回读 | 几 ms | **否** |

**这正是"辨识出 7.5 ms 延时、机器人却不会倒"的原因**：那 7.5 ms 主要**不在回路里**。
回路内只有电机内部那零点几毫秒。

### 7.3 ⚠️ 数据链路延时 ≠ 回路延时

如果 PD 在电机端、而**辨识用的 $q$ 是上位机回读的**，那么数据里含一段**回读延时** $T_{up}$。
拟合会把它当成 $T_d$ 认出来（round-trip 就是这样：**数据从哪来、延时就在哪**）。此时若把
$T_d$ 当"回路内延时"放回仿真，就等于把一段**本来不在回路里**的延时塞进了回路：

- 仿真会**人为变脆**（G1 那个 18.9 Hz 极限环就是这么来的）；
- 辨识出的 $I_a/d/\tau_f$ 会为了补偿它而被带偏。

**正确归属**：$T_{up}$ 属于**观测/记录通道**，不属于控制回路。仿真里应把它加在"算损失时把
仿真状态延迟 $T_{up}$ 再与数据比较"这一侧，而不是加在执行器的力矩上。

### 7.4 真机测量方案

目标是把三个量分开：$T_{down}$（指令下行）、$T_{up}$（数据回读）、$T_{loop}$（回路内那一段）。
**只关心 $T_{loop}$** —— 它才决定稳定性。

**准备（三项都必须做）**

1. **关节悬空**：机器人吊起来或单腿抬起，关节不受重力载荷、不接触任何东西。
   带载时重力矩会主导阶跃响应，纯滞后被淹没。
2. **安全**：力矩限幅设保守值；$kp$ 从小到大**分档**加，不要一次给大值；急停在手边。
3. **日志**：以最高可用频率同时记录 `(t_send, q_des, q, dq, tau)`。
   ⚠️ 必须记录**发送时刻** `t_send`，不能只记命令值 —— 否则无法对齐时间轴。

---

**实验 A：开环力矩阶跃 → 量"往返总延时" $T_{down}+T_{up}$**

1. 令 `kp = kd = 0`（纯力矩模式）。
2. 在某个已知时刻 $t_0$ 下发一个小的力矩阶跃 $\tau_0$（关节自由时 $\ddot q = \tau_0/I$）。
3. 看反馈：**优先看 `tau` 反馈的跳变时刻**（比看运动更直接，不受惯量/摩擦影响）；
   也可以看加速度的起始点。

判读：$\Delta t_A = T_{down} + T_{up}$（往返总和）。

> ⚠️ **这一步永远分不出下行和上行**：你观测到的每个量本身都被回读延时推迟了。
> 单靠上位机一个时钟，只能拿到往返和。要分开只能靠实验 C 或实验 D。

---

**实验 B：闭环位置阶跃 → 直接看"回路内延时" $T_{loop}$**

1. 用**真实 PD** 发一个位置阶跃（幅值取行程的 10–20%，别贴限位）。
2. 看响应曲线**起始处有没有"纯滞后平台"**（命令已跳变、$q$ 完全不动的那一段）。

判读：

| 观察 | 含义 |
|---|---|
| 几乎没有纯滞后平台，只有上升时间 | PD 在**电机端** ⇒ $T_{loop}\approx0$ |
| 有明显纯滞后平台，量值 ≈ $\Delta t_A$ | PD 在**上位机** ⇒ $T_{loop}\approx T_{down}+T_{up}$ |
| 平台量值介于两者之间 | 部分在回路内（如状态估计/滤波引入的） |

实操提示：纯滞后常常被摩擦"抹圆"而看不清楚（$q$ 是被 PD 慢慢推起来的）。
所以**实验 B 只能定性，要定量必须做实验 C**。

---

**实验 C（决定性）：临界增益实验 → 反解 $T_{loop}$**

原理：让关节**自己振起来**，用 §3.5 的判据反推延时。在临界点上 $T_{loop} = T_{crit}$。

1. 关节悬空，给一个恒定的小目标位置（或很小的正弦）。
2. $kp$ **分档往上加**（每档等几秒稳定），同时盯 $q$ 的时域波形。
3. 记录两个量：
   - $kp_{crit}$ = 开始出现**等幅振荡**（不衰减）的那一档增益；
   - $f_{crit}^{实测}$ = 该振荡的**频率**（对 $q$ 做 FFT，或数零点）。
4. 把 $P=kp_{crit}$（$kd$ 用你设的值）、$I$、$d$ 代进 §3.5 的 `hopf()` 得到 $T_{crit}$：
   $$T_{loop} \;\approx\; T_{crit}\big(I,\ d,\ kp_{crit},\ kd\big)$$
5. **交叉验证**：把解出的 $T_{loop}$ 与实测 $f_{crit}$ 对一遍 ——
   模型的起振频率应与实测吻合（§3.5 的 S800 实例误差 1.6%；不吻合说明 $I$ 或 $d$ 取错了）。

> ⚠️ 安全：必须悬空 + 小幅 + 力矩限幅；$kp$ 分档递增，出现等幅振荡立刻停。
> 这个实验就是"把 S800 当初踩的坑主动复现一遍"，所以要在安全条件下做。

---

**实验 D（可选）：单独量 $T_{up}$**

若电机上报的状态里带**采样时戳/计数器**，比较它与上位机收到时刻，直接得到 $T_{up}$；
再与实验 A 的往返时间相减即得 $T_{down}$。SDK 不支持时可用"外部事件法"：
用手轻敲关节或用外部设备（示波器/高频相机）记录一个外部事件时刻，与上位机日志对齐。

---

**判读总表**

| 观察 | 结论 | 仿真里该把延时放哪 |
|---|---|---|
| $T_{loop}\approx0$（实验 B/C），往返几 ms（实验 A） | PD 在电机端 | **指令通道**（论文 Eq.1 / `PaceDCMotorCmdDelay`） |
| $T_{loop}\approx\Delta t_A$ | PD 在上位机 | **回路内**（现有 `PaceDCMotor`，用 $\omega_c T\lesssim0.613$ 复核） |
| 数据含 $T_{up}$ | （与上面独立） | 加在**观测通道**，不是回路里（见 7.3） |

### 7.5 与论文的关系、代价、当前选择

- **与论文的关系**：论文 Eq. (1) 就是指令延时；换成指令延时是**回归论文**，不是偏离。
  物理上也更贴近 Unitree 一类硬件（电机端用最新编码器算 PD，上位机只下发目标与增益）。
- **代价/风险**：
  - 换结构会改变**被辨识对象的语义**（延时到底在哪条链路上），所以**采集与拟合必须用同一种**；
  - 两种结构在数据上是**可区分**的：用指令延时采数据、用力矩延时去拟合，损失会停在明显
    更高的平台（`g1_sim2sim_guide.html` 的对照实验）；
  - 真机上这一点尚未实测，**上真机前应先按 7.4 确认延时量级与位置**。
- **当前选择**：暂不换执行器，只把 $T_d$ 降到增益能承受的范围。理由：改动面最小
  （S800 的整条流水线不受影响），且立刻可验证（floor test 的散布是否收窄到 1e-13）。
  若后续要做面向真机的保真度，再按论文换指令延时。
- ⚠️ **round-trip 验证不了结构**：sim-to-sim 里采集与拟合共用同一个仿真，延时放哪都自洽，
  round trip 通过只能说明"流程和可辨识性没问题"。**结构对不对必须上真机按 7.4 测。**

## 八、一句话总结

> 延时的**位置**（在回路内还是在回路外）决定闭环稳不稳：**传感器延时和力矩延时在回路内**、
> **指令延时不在**；延时的**长度**决定离失稳多远。论文的频域模型（Eq.1）把集总延时放在
> 输入端，仓库实现放在力矩上 —— 两者在低增益小延时下近似等价，在高增益下差别是"稳 / 不稳"。
>
> 对**仿真**：只要实现了力矩延时，就必须保证 $\omega_c T \lesssim 0.613\ \text{rad}$
> （精确判据用 §3.5 的 $T_{crit}$）。超限的代价不是"精度差一点"，而是极限环把损失地形
> 搅成针尖 + 护城河，优化器会主动离开正确解。
>
> 对**真机**：位置不是口味问题，取决于 **PD 在哪算 + 数据从哪读**（§7.2）。G1 的 SDK 结构
> （下发 `q/kp/kd`、电机端算 PD）意味着真正的回路内延时只有电机内部那零点几毫秒，
> 而辨识出的几毫秒主要来自总线回读 —— **那一段属于观测通道，不能塞回回路里**（§7.3）。
> 上真机前按 §7.4 的阶跃/临界增益实验确认。
