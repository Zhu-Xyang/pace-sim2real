# Chirp 信号 Bias 和 Scale 设计文档

## 1. 起点：chirp 信号公式

```python
chirp_signal = sin(phase)                      # 无量纲，范围 [-1, +1]
target = (chirp + bias) * direction * scale     # 最终下发的关节目标位置 (rad)
```

- **chirp**：扫频正弦，从低频到高频，激励系统的全频带响应
- **direction**：±1，左右对称关节运动方向取反
- **bias**：振荡中心偏移 (rad)，决定关节围绕哪个位置摆动
- **scale**：振幅 (rad)，决定摆动多大

数据流是：`chirp [-1,1]` → `乘 scale 变成 rad` → `直接作为绝对关节位置目标` → PD 控制器跟踪

> 注：`data_collection.py` 中 action 的 `scale=1.0`，即 actions 直接就是关节目标位置（单位 rad），没有归一化。

---

## 2. Scale 设计：三个约束取最小值

scale 越大，激励越强，信噪比越高，辨识越准。但 scale 不能无限大，受三个物理约束：

### 约束 A：URDF 关节限位

```
关节目标位置范围 = [bias - scale, bias + scale]
必须在 URDF 限位 [lo, hi] 之内
```

对于 bias=0 的对称关节：

```
scale ≤ min(|lo|, |hi|) × 安全系数
```

对于 bias=URDF 中心的关节：

```
scale ≤ (hi - lo) / 2 × 安全系数
```

安全系数取 **0.4**（即只用 40% 可用范围），留 60% 余量给 PD 跟踪误差和瞬态超调。

**为什么 0.4 而不是 0.5？** 因为 PD 控制器跟踪 chirp 信号时会有超调和滞后，特别是高频段。如果用满 50%，高频段的目标位置可能瞬时超限被 clip，破坏 chirp 的纯正弦性，引入谐波失真。

### 约束 B：力矩饱和

```
所需力矩 ≈ kp × scale + kd × ω_max × scale
必须 ≤ effort_limit × 0.8
```

其中 `kp`、`kd` 来自 `kpkd.py`，`ω_max = 2π × f1 × scale`（chirp 最高频时的角速度幅值）。

安全系数取 **0.8**（只用 80% 峰值力矩），留 20% 给重力补偿和摩擦等额外负载。

**关键例子**：WRIST 关节 `effort_limit=5 Nm`，`kp=12.5`，即使 `scale=0.15`：

```
τ ≈ 12.5 × 0.15 = 1.875 Nm  (已经用掉 37% 峰值)
加上 kd 项和高速段，接近饱和
→ scale 被力矩约束压到 0.15
```

### 约束 C：物理合理上限 (phys_cap)

这是一个工程经验约束，防止某些关节虽然 URDF 和力矩都允许大范围运动，但实际会产生问题：

| 关节类型 | phys_cap | 理由 |
|---------|---------|------|
| HIP_PITCH / KNEE_PITCH | 0.50 | 承重关节，大幅摆动可激发惯量 |
| HIP_ROLL / HIP_YAW / TORSO_YAW | 0.40 | 避免躯干过度扭转导致悬挂姿态失稳 |
| ANKLE_PITCH | 0.30 | 小关节，过大激励会打脚 |
| ANKLE_ROLL | 0.15 | URDF 限位极小，约束 A 自然生效 |
| SHOULDER / ELBOW_PITCH | 0.40 | 手臂关节，避免自碰撞 |
| ELBOW_YAW | 0.35 | 力矩较小 (52 Nm)，防饱和 |
| WRIST | 0.15 | 力矩极小 (5 Nm)，约束 B 自然生效 |

### 最终 scale = min(A, B, C)

```
scale = min(URDF半范围 × 0.4, 80%力矩上限, phys_cap)
```

## 3. Bias 设计：对称 vs 不对称决策树

```
对每个关节：
  计算 URDF 限位 [lo, hi]
  如果 bias=0 时对称余量 = min(|lo|, |hi|) ≥ 0.25 rad
    → bias = 0（足够激励，悬挂零位最简单）
  否则
    → bias = (lo + hi) / 2（移到 URDF 范围中心，最大化可用振幅）
```

### 为什么阈值是 0.25？

CMA-ES 辨识需要足够的信噪比。chirp 激励产生的关节运动幅度至少要 0.25 rad（约 14°）才能在轨迹 MSE 中产生可辨识的差异。如果对称余量小于 0.25 rad，说明 bias=0 时可用振幅太小，信噪比不足。

### 哪些关节需要偏移？

关键问题是 URDF 限位的**不对称性**：

| 关节 | URDF lo | URDF hi | 对称余量 | 问题 | bias | bias 后可用范围 |
|------|---------|---------|---------|------|------|-------------|
| KNEE_PITCH | -0.262 | 2.355 | 0.262 | 负向只能弯 15° | 1.046 | ±1.309 |
| ANKLE_ROLL | -0.349 | 0.174 | 0.174 | 正向只能转 10° | -0.087 | ±0.262 |
| SHOULDER_ROLL | -0.384 | 2.487 | 0.384 | 负向只能转 22° | 1.052 | ±1.434 |
| ELBOW_PITCH | -2.295 | 0.288 | 0.288 | 正向只能弯 16° | -1.004 | ±1.291 |
| WRIST_ROLL | -3.142 | 3.142 | 3.142 | 对称！但力矩约束 | 0.000 | — |

前 4 个关节的共同特点：**URDF 限位严重不对称**，一侧范围远大于另一侧。在 bias=0 时，chirp 的负半周期（或正半周期）很快撞限位，scale 被压到极小值（0.07~0.15），信噪比严重不足。

WRIST_ROLL 虽然范围对称（±π），但 `effort_limit=5 Nm` 太小，力矩约束 B 先生效，bias 保持 0。

## 4. 完整推导示例

以 **KNEE_PITCH** 为例：

```
URDF 限位: [-0.262, 2.355] rad
力矩限制: 415 Nm, kp=240, kd=5.8

如果 bias=0:
  对称余量 = min(0.262, 2.355) = 0.262
  约束A: 0.262 × 0.4 = 0.105 rad  ← 最小，生效
  约束B: 415×0.8 / (240 + 5.8×2π×15×0.105) ≈ 1.15 rad
  约束C: 0.50 rad
  → scale = 0.105 (只能摆 ±6°，信噪比差)

如果 bias=1.046 (URDF中心):
  半范围 = (2.355-(-0.262))/2 = 1.309
  约束A: 1.309 × 0.4 = 0.524
  约束B: 仍约 1.15
  约束C: 0.50  ← 最小，生效
  → scale = 0.50 (能摆 ±29°，信噪比提升 4.8 倍)
```

bias=1.046 意味着膝盖初始弯曲 60°，chirp 围绕这个位置摆动 ±29°（从 31° 到 89°），完全在 URDF 范围内，且力矩不饱和。

## 5. 镜像对称性

左右对称关节的 bias 和 direction 配合：

### 屈伸型关节（如 KNEE_PITCH）

左右腿弯曲方向相同（都向前弯），所以 bias 相同：

```python
# 左腿 KNEE_PITCH
bias = +1.046, direction = +1
target = (chirp + 1.046) × 1 × 0.5

# 右腿 KNEE_PITCH
bias = +1.046, direction = -1
target = (chirp + 1.046) × (-1) × 0.5
```

direction=-1 是让 chirp 的相位反转，这样左右腿运动镜像对称。

### 侧摆型关节（如 ANKLE_ROLL）

左右定义本身就是镜像的，所以 bias 取相反符号：

```python
# 左: bias=-0.087, dir=+1  → 中心偏左
# 右: bias=+0.087, dir=-1  → 中心偏右（镜像）
```

对 Anymal-D 机器人（`anymal_d_simple_description/urdf/anymal.urdf`）应用同一套设计法则，对比 ETH 原始设计。

### 7.3 与 ETH 原始设计的对比

| 关节 | ETH bias | ETH scale | 我们的 bias | 我们的 scale | 差异 |
|------|---------|-----------|-----------|------------|------|
| HAA | 0.0 | 0.25 | 0.0 | 0.244 | ≈一致 ✅ |
| HFE | 0.4 | 0.5 | 0.0 | 0.500 | bias 不同 |
| KFE | 0.8 | **-2.0** | 0.0 | 0.500 | **差异 4 倍** ⚠️ |

### 7.4 关键发现：KFE scale=-2.0 与电机饱和

ETH 原始设计中 KFE 的 scale=-2.0 远超力矩和速度限制：

```
scale=2.0 时:
  ω_max = 2π × 10 × 2.0 = 125.7 rad/s  (是 velocity_limit 8.5 的 14.8 倍!)
  τ_max = 85 × 2.0 + 0.6 × 125.7 = 245.4 Nm  (是 effort_limit 89 的 2.76 倍!)
```

**DC 电机力矩-速度饱和曲线**：

| ω (rad/s) | 可用力矩 (Nm) | % of effort_limit |
|-----------|-------------|-------------------|
| 0 | 140 | 157% |
| 4 | 74 | 83% |
| 8.5 (=vel_limit) | **0** | **0%** |
| >8.5 | 0 | 0% |

当 scale > 0.135 时，ω_max > velocity_limit，电机进入饱和区——**高频段电机完全无法跟随 chirp，位置响应大幅滞后**。

**这并非设计错误，而是 ETH 有意为之**：

1. **低频段**（0-5s）：电机能跟随 chirp → 激励惯量/阻尼/摩擦的线性响应
2. **高频段**（5-20s）：电机无法跟随 → 滞后本身是信号，暴露 armature/delay/damping 的非线性动态
3. CMA-ES 通过匹配这个滞后行为来辨识参数——**饱和区是参数最可辨识的区域**

负号 scale=-2.0 意味着 chirp 相位翻转，膝关节与髋关节反向运动（四足自然步态模式）。

bias=0.8 (HFE) 和 bias=0.8 (KFE) 是**悬挂站姿偏移**（髋屈 23°、膝弯 46°），不是 URDF 约束驱动的——Anymal URDF 范围 ±3π 完全对称，不需要 bias 偏移。

### 7.5 对 S800 设计的启示

| 维度 | Anymal ETH 原始 | S800 当前 | 评估 |
|------|---------------|----------|------|
| scale 大小 | KFE=2.0 (饱和区) | KFE=0.5 (线性区) | S800 更保守 |
| bias 来源 | 站姿偏移 (物理) | URDF 中心 (约束) | 不同动机 |
| 激励区域 | 线性 + 非线性 | 仅线性 | S800 可能辨识不足 |
| 电机饱和 | 高频段完全饱和 | 从不饱和 | S800 丢失饱和辨识 |

**核心结论**：S800 的 scale 设计过于保守（全部 ≤ 0.5），所有关节始终在线性区运行。CMA-ES 无法从纯线性响应中辨识 armature/delay 等参数——因为这些参数的非线性效应只在饱和区才显著。

**建议**：对 S800 的大关节（HIP_PITCH/KNEE_PITCH, kp=240, effort_limit=415Nm）适当增大 scale 到 0.8-1.0，让高频段进入电机饱和区，提升参数可辨识性。小关节（WRIST）因力矩极小，保持当前保守设计。
